# Loom 0.5.0 — the call

Date: 2026-11-07
Status: build spec. This version is the callable surface. It does not replace PROTOCOL.md. PROTOCOL.md is the law. This file is the contract a harness calls.

## 1. Intent

Loom is one agent. Claude can call it. Codex can call it. A later inside, where one harness calls the other as a subagent, is the same agent. The caller cannot tell which inside ran.

the governance layer governs: what may be done, budgets, review, escalation. A model reply is not authority. the harness is the coding harness: one loop, roles as configs. Loom is neither. Loom is the unit that loop dispatches. Today that unit is a dozen scripts a conductor has to remember. 0.5.0 makes it one call.

## 2. Why this version, why now

The mechanics exist and the drills passed (D1–D4, see `drills/EVIDENCE-2026-11-07.md`). The first real Orca run then found four gaps that are still open:

| Issue | What broke |
| --- | --- |
| #29 | A real `worker-start` receipt has no `worktree.path`. The workspace is `result.workspace` = `<repo-id>::<absolute-path>`. Loom only found the folder by a fallback. |
| #30 | Orca keeps a new-top-level worker worktree open (`keptOpen: true`). Loom never releases it. |
| #31 | A handled `failed` / `blocked` / `ready` stays in `status.sh` forever. Status stops meaning "what waits for a person". |
| #33 | Workers leave evidence logs at the workspace root. Harvest commits everything not excluded, so logs land on the consumer branch, outside the ticket scope. |
| #35 | The Orca command map. Specified here. Not all of it is this version. |

0.5.0 closes #29, #30, #31, #33 and gives every harness the same call. #35's remaining rows stay open. They are listed in section 8 so the next version does not rediscover them.

## 3. The sameness rule

One command. One JSON object on stdout. Exit 0 if and only if `ok` is true.

```
bash ops/loom <verb> [args]
```

A caller that reads only that object must not be able to tell:

- whether the worker was a local process or an Orca worker
- whether the agent behind Orca was Codex or anything else
- which harness issued the call

Forbidden in this version: a field that names the harness, the model, the owner, or the machine. The protocol already refuses a person/identity entity. The call does not add one.

The inside may change later (a harness calling another harness as a subagent, still through Orca's `worker-start --agent`). The command, the object, and the four report states do not change. A new inside that needs a new field is a new version, not a quiet addition.

## 4. What 0.5.0 is, and is not

Goals, in order:

1. Any harness runs one command and gets one object back.
2. The four open gaps above are closed, each with a selftest case and a mutant.
3. Eval's two outputs are both recordable: accept (a Ticket) and ignore (a line in the state dir, no issue).
4. The law documents a caller would read no longer describe the v0 shape.

Non-goals:

- Loom does not spawn Claude or Codex itself. The caller is the harness. Orca starts the worker when the caller says `start`. Putting a model inside Loom is a later version, and it must keep this command.
- Loom does not push, open a PR, or merge. `collect` fetches the branch into the consumer checkout and stops.
- Loom does not poll Orca. Orca wakes the conductor. Scripts may `--peek` later; they do not `check`.
- Loom does not implement the rest of issue #35 in this version.
- No daemon, no MCP server, no new language, no new package. Bash, `jq`, `git`, `gh`, and the Orca CLI when the consumer requires it.
- No second protocol for one harness.

Anti-goals (a failure even if the command exits 0):

- Two envelopes, or prose on stdout that a caller must interpret.
- A silent fallback from a required Orca executor to the local launcher.
- A stop or a release claimed when Orca did not confirm it.
- Status that still lists an assignment a person has already dealt with.
- Evidence logs committed onto the consumer branch.
- Anything identifying the owner written into a file, a log that gets committed, or a commit message Loom composes. The worker's fact string is the worker's; Loom does not add a name to it.
- Inferring a report state from free text. Structured fields or nothing.

## 5. Constraints

- Bash 3.2+. No arrays-of-arrays tricks that need Bash 4.
- Tickets remain GitHub issues. `gh` is the issue client. The active account for this repo is RedKnight13. This checkout's local git identity is `RedKnight13 <39779052+RedKnight13@users.noreply.github.com>`, signing off. The call does not write that identity into a consumer file.
- Dispatch still copies `user.name` and `user.email` from the consumer checkout into a local clone. That is existing behaviour. 0.5.0 does not invent a second identity. A consumer that must not carry another account sets its own local git identity; Loom copies what it finds and does not hard-code one.
- `$LOOM_STATE` (default `~/.loom`) stays conductor-only. Workers never write it.
- Assignment ids stay `<short>.<attempt>`. One live assignment per ticket.
- Report states a worker may write stay exactly four: `ready`, `blocked`, `failed`, `waiting`. Ack is not a fifth state a worker can emit.
- A failed `worker-start` is recorded and never retried.
- Silence or a timeout never authorizes stopping an Orca worker. `stop_unknown` changes nothing.
- Loom never closes a terminal itself. Release is `orchestration worker-release`.

## 6. The object

Every invocation prints exactly one JSON object to stdout, one line, no other stdout. Diagnostics stay on stderr. Keys are always present.

```json
{"v":"0.5.0","cmd":"status","ok":true,"state":"waiting","fact":"nothing waits for a person","id":null,"ticket":null,"items":[],"actions":[]}
```

| Key | Type | Rule |
| --- | --- | --- |
| `v` | string | Always `0.5.0` until the version file changes. Read from `VERSION` at the repo root. |
| `cmd` | string | The verb, even on usage failure. |
| `ok` | bool | True only when the verb did what it claims. |
| `state` | string | One of the states in the table below. |
| `fact` | string | One line. Tabs and newlines replaced with a space. Never empty on failure. |
| `id` | string or null | Assignment id when the verb has one. |
| `ticket` | number or null | Issue number when the verb has one. |
| `items` | array | Status rows. Empty for every other verb. |
| `actions` | array of strings | Watchdog lines from `watch`. Empty otherwise. |

Exit codes: `0` when `ok` is true. `1` when the verb ran and failed. `2` when the invocation itself is wrong (unknown verb, missing flag). Usage failure still prints the object, with `ok: false` and `state: "failed"`.

### 6.1 Envelope states

These are call states. They are not a new worker vocabulary.

| State | Who sets it | Means |
| --- | --- | --- |
| `accepted` | `accept` | A Ticket was opened. `ticket` is the issue number. |
| `ignored` | `ignore` | Eval said no. Recorded. No issue. |
| `dispatched` | `dispatch` | An assignment exists. `id` is set. `fact` is the workdir, or the Orca "workspace is created at start" line. |
| `launched` | `launch` | Local worker exited and was harvested. `fact` is the script's outcome line. |
| `started` | `start` | Orca confirmed a worker. |
| `harvested` | `harvest` | Orca worker's `REPORT.md` is folded. The report state is in `fact`, not in `state`, so the envelope does not pretend the call state is the worker state. |
| `stopped` | `stop` | Orca confirmed the stop. |
| `released` | `release` | Orca confirmed the release. |
| `verified` | `verify` | Checks exited 0. |
| `collected` | `collect` | Branch is in the consumer checkout. Never pushed. |
| `acked` | `ack` | The assignment no longer waits. History kept. |
| `waiting` | `status`, `version` | Nothing waits, or this is a version query. |
| `ready` | `status` | At least one unacked `ready`, and nothing blocked, failed, or stale. |
| `blocked` | `status` | A person must answer. Beats every other status row. |
| `failed` | `status`, or any verb that failed | A person must look, or the verb did not succeed. |
| `stale` | `status` | An Orca worker is past its limit. Loom did not stop it. |
| `release` | `status` | A kept-open Orca workspace is settled and collected and not released. |

Status priority, top-level `state` only: `blocked`, then `failed`, then `stale`, then `release`, then `ready`, then `waiting`. A question beats a result. A kept-open workspace does not hide a failure.

An item is `{"id","state","fact"}`. `state` there is the row's own kind (`ready`, `blocked`, `failed`, `stale`, `release`), not the priority winner.

### 6.2 Verbs

```
loom version
loom accept --consumer FILE --short NAME --title T --scope S --out O --done D
loom ignore --consumer FILE --short NAME --reason TEXT
loom dispatch --consumer FILE --issue N [--executor auto|local|orca]
loom launch ID -- CMD...
loom start ID [--agent NAME]
loom harvest ID
loom stop ID
loom release ID
loom watch --until ID|all [--every SEC] [--limit-min N]
loom status
loom verify ID [--baseline]
loom collect ID
loom report ID STATE FACT
loom ack ID FACT
loom detect
```

`FILE` is a consumer toml. `N` is a positive integer. `STATE` is one of the four worker states. `FACT` is one non-empty line. `NAME` for `--agent` is `[a-z0-9-]+`. `--` on `launch` is required and is the worker command, passed through, not interpreted.

Each verb is a wrapper over the script that already owns the mechanism, except `ignore` and `ack`, which are new because the mechanism had no place for them.

| Verb | Script | Success `state` | `id` / `ticket` |
| --- | --- | --- | --- |
| `version` | none | `waiting` | both null. `fact` is `loom 0.5.0`. |
| `accept` | `ticket.sh` | `accepted` | `ticket` parsed from the issue URL. `id` null. |
| `ignore` | new, append-only | `ignored` | both null. |
| `dispatch` | `dispatch.sh` | `dispatched` | `id` is the last line. `ticket` is `N`. `fact` is the first line. |
| `launch` | `launch.sh` | `launched` | `id` as given. |
| `start` | `orca.sh start` | `started` | `id` as given. |
| `harvest` | `orca.sh harvest` | `harvested` | `id` as given. |
| `stop` | `orca.sh stop` | `stopped` | `id` as given. |
| `release` | `orca.sh release` | `released` | `id` as given. |
| `watch` | `heartbeat.sh`, then the status rules | the status priority | `id` is `--until` unless it is `all`, then null. |
| `status` | `status.sh` | the priority | both null. Rows in `items`. |
| `verify` | `verify.sh` | `verified` only on exit 0; otherwise `failed` and `ok: false` | `id` as given. |
| `collect` | `collect.sh` | `collected` | `id` as given. |
| `report` | `report.sh` | the state that was recorded | `id` as given. |
| `ack` | `ack.sh` | `acked` | `id` as given. |
| `detect` | `orca.sh detect` | `waiting` if ready, else `failed` and `ok: false` | both null. |

On any script failure, `ok` is false, `state` is `failed`, and `fact` is the last stderr line, else the last stdout line, else `exit N`. The object is still the only stdout.

`accept` does not judge. The caller already decided to accept. `ignore` does not judge. The caller already decided to ignore. Loom records the decision and does not invent one. That is Eval staying with the conductor, which is the harness on the other side of the call.

### 6.3 Ignore

Append one JSON line to `$LOOM_STATE/decisions.jsonl`. Create the file if needed. Do not open an issue. Do not update a Ticket.

```json
{"at":"<ISO-8601>","decision":"ignore","repo":"<from the consumer toml>","short":"<short>","reason":"<text>"}
```

Refuse an empty reason, a short name dispatch's parser would refuse, or a missing consumer file. The short name is checked with `loom_short` against a one-line mandate fragment, so a bad name fails the same way a ticket would. The reason is stored literal. It is not evaluated.

Accepting the same trigger twice is still the caller's job. Loom does not dedupe ignores. Two ignore lines are two recorded decisions.

### 6.4 Ack (gap #31)

`ack.sh <id> "<why>"` sets `.acked` on the assignment:

```json
"acked": {"at": "<ISO-8601>", "fact": "<why>"}
```

Rules:

- `why` is one non-empty line. No newline, no markdown heading.
- Refuse if the assignment is live (local PID match, or Orca `running` / `starting`).
- Refuse a second ack. The first fact stands. Rewriting it would be a silent history edit.
- Do not append a report. The four states stay the worker vocabulary. The reports array is the history.
- `status.sh` skips report rows (`ready` / `blocked` / `failed`) when `.acked` is set.
- A kept-open unreleased workspace still produces a `release` row after ack. Ack is not a substitute for release. Hiding that row would recreate #31 under another name.
- A stale running Orca worker cannot be acked, because ack refuses a live worker. The owner stops it through `stop`, which only records a stop Orca confirmed.

### 6.5 Workspace receipt (gap #29)

`orca.sh start` reads the workspace in this order, and stops at the first that is a real directory:

1. `workspace`, split on the last `::`. The right-hand side is the path. A value with no `::` is not a path.
2. `worktreePath`, `worktree_path`, or `worktree.path` (the old search).
3. `orca worktree show --worktree name:<id> --json`, first string `path`. This fallback stays.

The selftest stub returns the real shape and not `worktree.path`:

```json
{"ok":true,"result":{"dispatchId":"...","taskId":"...","runId":"...","workspace":"<repo-id>::<absolute-path>","terminal":{"id":"..."},"keptOpen":true}}
```

`keptOpen` is stored as `.executor.kept_open` (bool). `dispatchId` is stored as today.

### 6.6 Release (gap #30)

`orca.sh release <id>` calls `orchestration worker-release --dispatch <id>` and records the receipt at `$LOOM_STATE/<id>.orca-release.receipt`.

Refuse, and change nothing, unless all of these hold:

- executor kind is `orca`
- executor state is `settled`
- `.collected_sha` is a 40-hex sha (collect wrote it)
- `.executor.released` is not true
- `.executor.dispatch` is non-empty

A non-zero exit from Orca, or a receipt that is not ok, changes nothing and exits 1. Loom does not kill a terminal, delete a worktree, or delete a branch in this version. `worktree rm` is a later #35 row, after a PR has merged. Release means "no one will use this chat", which is what Orca's receipt asked for.

`collect.sh` writes `.collected_sha` after a successful collect, under the state lock. It still never pushes. An Orca worktree that shares the checkout's repository is already home; collect records the sha without a fetch, as it does today.

`status.sh` adds one row when `kept_open` is true, state is `settled`, `collected_sha` is set, and `released` is not true:

```
<id>\trelease\tkept-open workspace not released (Orca dispatch <id>)
```

### 6.7 Evidence (gap #33)

Workers put logs under `.loom/` at the workspace root. Loom tells them so in `WORK.md`. Harvest:

1. Ensures `WORK.md`, `REPORT.md`, and `.loom/` are in the workdir's exclude list (local clone and Orca common dir).
2. If `.loom` exists, it must be a real directory, not a symlink. Copy it to `$LOOM_STATE/<id>.evidence/` (replace any previous copy). A symlink is an error, not a follow.
3. Then stages and commits, as today, with one retry after a fixer hook.

`.loom/` is not in the commit. Files the worker leaves at the root are still committed. The gap was that Loom never named a place. It does not start refusing root files in this version; that would be a new policy the ticket did not ask for.

## 7. Roles, unchanged

| Role | Call |
| --- | --- |
| Owner | Answers `blocked`. Approves anything irreversible. The only authority above the Mandate. |
| Conductor | The harness that calls `ops/loom`. Eval, dispatch, review, push, PR, merge. The only role that pushes, always under the owner's GitHub name. |
| Worker | Reads `WORK.md`. Writes files and one `state:` line. Never runs git. Never writes `$LOOM_STATE`. Never pushes. |

0.5.0 does not add a fourth role. "Standalone agent" means the call, not a new person in the protocol.

| `orchestration worker-show --dispatch` | Before harvest, prove the Dispatch is settled. Liveness for status, instead of Loom's own timestamps. |
| `orchestration worker-read --dispatch --source auto` | On failed or stale, save the transcript under `$LOOM_STATE/<id>.evidence/`. |
| `orchestration worker-abandon --dispatch` | Owner-decided fencing when a stop cannot be confirmed. |
| `orchestration worker-keep-open --dispatch` | Owner wants to keep talking. |
| `orchestration worker-list --run --include-remote` | Reconcile records after a conductor restart. |
| `orchestration request-show` and `--retry-request` | Crash-safe start/stop. A death mid-call asks Orca whether it took effect. Never start twice. |
| `worktree rm --worktree --delete-branch` | After the PR merges, not at release. |
| `orchestration check --peek --json` / `inbox` | Read `worker_done` without taking the mail. A mismatch with `REPORT.md` is a finding. Never script `check`. |
| `orchestration send` | A fix request after a failed verify. Not a new attempt. |
| `orchestration ask` / `reply` | A `blocked` question as a message. |
| `orchestration gate-create` / `gate-resolve` / `gate-list` | Owner decisions become Orca gates. |
| `orchestration task-update` | Mirror verified / failed onto the Orca task. |
| `run-create` / `run-use` / `run-current` / `run-show` / `run-list` | One Run per batch. A new session resumes. |
| `task-create` + `worker-start --task` | Ticket dependencies as a task DAG. |
| `worker-start --display-name --comment` | Assignment id and ticket URL in Orca metadata. |
| `reference add` / `find` / `list` | Attach the ticket, later the PR. Find a workspace by ticket. |
| `worker-start --model --effort` | Per-consumer policy in the toml. Not a Loom default. |
| `worker-start --timeout-ms` | Bound how long start waits. |
| `repo show` / `repo set-base-ref` | Refuse dispatch when the checkout is not registered. Keep the base ref aligned. |
| `worktree ps` / `worktree list` | Overview next to status. |
| `automations create` / `list` / `run` / `remove` | A heartbeat that does not need a session awake. |

Rules that already bind, and keep binding:

- Never poll or script `check`.
- A failed `worker-start` is never re-run blindly.
- Silence, a timeout, or unverifiable liveness never authorizes a stop.
- Let `worker-start` create workspaces. Loom does not make checkouts for Orca workers.

## 9. Identity

- Git operations on this repo use the RedKnight13 account only.
- No other account's name, email, or signing key is written by this version.
- The call object has no identity fields.
- `decisions.jsonl` stores the consumer repo slug, the short name, and the reason. Not a person.
- Commit messages Loom composes stay `loom(<id>): <state> — <fact>`. Loom does not append a name.

## 11. Calls made here, not by the owner

- The entry point is `ops/loom`, not a new binary and not an MCP server. A later MCP wrapper shells out to this command. It does not grow a second contract.
- Ack is a field, not a fifth report state.
- Status priority is blocked, failed, stale, release, ready, waiting.
- Release does not delete the worktree. That waits for the post-merge row in section 8.
- Root-level evidence files are still committed. Only `.loom/` is excluded. The worker is told where evidence goes.
- Ignore lines are not deduped.
- #35 is specified and left open, except the rows section 8 marks built.
