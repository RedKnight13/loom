# Loom 0.6.0 — compute host, placement, labels, Orca map

Date: 2026-11-07
Status: build spec. Extends 0.5.0. The call contract does not change: one command, one JSON object, exit 0 iff `ok`.

## 1. Intent

0.5.0 made Loom callable. 0.6.0 makes the call honest about where work runs, and finishes the Orca integration map.

| Issue | Rule it restores |
| --- | --- |
| #36 | Checks run on the consumer's compute host. A declared-but-unreachable host refuses; it never falls back to the conductor's machine. |
| #37 | Workers are placed on that host through Orca. Loom never lets Orca place a worker locally when a host is declared. |
| #38 | A Ticket carries its labels at creation, not after a second hand edit. |
| #35 | The Orca functions Loom needs, mapped to the Loom action each one serves. |

Owner's standing rule, verbatim: "why are you doing it here instead of agni1 ??" and "all compute runs on Agni, never the laptop."

## 2. Goals and non-goals

Goals:

1. `compute` and `compute_setup` in the consumer config; checks over SSH, no local fallback.
2. `orca.sh start` resolves and uses the Orca host; refuses when it is unknown or not connected.
3. `ticket.sh --label` (repeatable), with `loom-ready` defaulted when the repo has it.
4. The #35 rows land as Loom subcommands, each with a selftest case.

Non-goals:

- Loom does not install anything on a compute host. `compute_setup` is a command the consumer declares; if it fails, that is "could not run", not a test failure.
- Loom does not connect Orca to a host. Connecting is the owner's act. Loom refuses until the host is connected.
- Loom does not poll Orca. `check --peek` and `inbox` are read-only snapshots; `check` without `--peek` is never scripted.
- Loom does not create scheduled automations. It exposes the verb; scheduling stays the owner's.
- No new language, daemon, or MCP server.

Anti-goals:

- Silent local execution when `compute` is declared.
- A checks failure and an unreachable host reported the same way.
- A worker placed locally while the consumer names a host.
- `worker-abandon` recorded as a stop.
- Harvest claiming a worker settled without asking Orca.

## 3. Consumer config additions

```toml
compute          = "agni2"                 # string or array, tried in order
compute_setup    = ". ~/.venvs/x/bin/activate"   # optional, runs on the host
compute_selector = "--host ssh:<id>"       # optional exact Orca selector
model            = "…"                     # optional, worker-start --model
effort           = "high"                  # optional, requires model
start_timeout_ms = 900000                  # optional, worker-start --timeout-ms
```

Validation: `compute` is a non-empty string or array of non-empty strings. `compute_setup` is a single-line string. `compute_selector` starts with `--` and is single-line. `model` and `effort` are whitespace-free strings. `start_timeout_ms` is a positive integer. Unknown keys stay rejected; nothing is evaluated at parse time.

`dispatch.sh` records `.compute` (array, or null), `.compute_setup`, `.compute_selector`, `.model`, `.effort`, `.start_timeout_ms`.

## 4. Checks on the compute host (#36)

Implemented by `ops/verify.sh` and `ops/lib.sh`:

1. Hosts come from the record's `.compute`. `--on HOST` names one for a single run, for an assignment dispatched before its consumer declared a host.
2. `loom_compute_pick <host>...` returns the first host where `ssh -o BatchMode=yes -o ConnectTimeout=10 <host> true` succeeds. `LOOM_SSH` names the binary (the selftest stubs it).
3. No host reachable, with a host declared: **refuse**. No run is recorded; the checks never run on the conductor's machine.
4. Otherwise: bundle the exact commit, stream it to the host over ssh, build a fresh tree in `$HOME/.loom-remote/<id>`, run `compute_setup` then the checks under the caller's umask, stream the log back to `$LOOM_STATE/<id>.checks-<kind>.log`, record the host in `checks_runs`, and remove the remote folder.
5. Exit 126/127/255 is **could not run**: a failing `compute_setup` or a broken ssh is never a test failure.
6. Without `compute`, checks run locally as before.

`loom compute --consumer FILE` resolves the list now and names the chosen host.

## 5. Placement (#37)

`orca.sh start`:

1. If the record's `.compute` is empty or null, behave as 0.5.0 (local placement).
2. Else take the first name and find it in `orca host list --json` (`result.hosts[]`) by `name` or `id`.
3. Missing → refuse, record nothing started, fact names the host.
4. `connected != true` (and not a local host) → refuse the same way. Loom does not connect it.
5. Otherwise pass `--on <name>` to `worker-start` and record `.executor.placement = {host, selector}`.
6. A consumer may set `compute_selector` for an exact Orca selector; it is validated to begin with `--` and is used verbatim instead of `--on`.

`orca.sh hosts` prints `name<TAB>connected<TAB>selector`; `loom hosts` wraps it as the object with one item per host.

## 6. Ticket labels (#38)

`ticket.sh` gains repeatable `--label NAME`, validated `^[A-Za-z0-9][A-Za-z0-9 ._-]*$`. Duplicates collapse.

Default: if `gh label list --repo <repo> --json name` contains `loom-ready`, add it unless the caller passed `--no-default-label`. A repo without that label is not an error; a failed listing only skips the default.

`gh issue create` receives one `--label` per label.

## 7. The Orca map (#35)

Envelope addition: a pass-through Orca verb and `compute` report `state: "complete"`. They did what they were asked and the fact names the result. No other object key changes.

| Orca command | Loom verb |
| --- | --- |
| `status` | `orca.sh detect`, `loom detect` |
| `host list` | `orca.sh hosts`, `loom hosts` |
| `orchestration worker-start` | `orca.sh start`, `loom start` (placement applied) |
| `orchestration worker-stop` | `orca.sh stop`, `loom stop` |
| `orchestration worker-release` | `orca.sh release`, `loom release` |
| `orchestration worker-show` | `orca.sh show`, `loom show`. Harvest asks it first and refuses a clearly active dispatch. |
| `orchestration worker-read` | `orca.sh read`, `loom read`. Writes `$LOOM_STATE/<id>.evidence/orca-transcript.txt`. |
| `orchestration worker-abandon` | `orca.sh abandon`, `loom abandon`. Records `failed / owner_fenced`, never `stopped`. |
| `orchestration worker-keep-open` | `orca.sh keep-open`, `loom keep-open` |
| `orchestration worker-list` | `orca.sh list`, `loom list` |
| `orchestration request-show` | `orca.sh request`, `loom request` |
| `orchestration check --peek` | `orca.sh peek`, `loom peek`. Never `check` without `--peek`. |
| `orchestration inbox` | `orca.sh inbox`, `loom inbox` |
| `orchestration send` | `orca.sh send`, `loom send` (`--to dispatch:<id>`) |
| `orchestration ask` / `reply` | `orca.sh ask`, `orca.sh reply`, `loom ask`, `loom reply` |
| `orchestration gate-create` / `gate-resolve` / `gate-list` | `orca.sh gate …`, `loom gate …` |
| `orchestration task-create` / `task-update` | `orca.sh task …`, `loom task …` |
| `run-create` / `run-use` / `run-current` / `run-show` / `run-list` | `orca.sh run …`, `loom run …` |
| `worker-start --display-name --comment` | `start` always sets both from the assignment id and ticket |
| `worker-start --model --effort` | consumer `model` / `effort` |
| `worker-start --timeout-ms` | consumer `start_timeout_ms` |
| `reference add` / `find` / `list` | `orca.sh reference …`, `loom reference …`. The ticket URL is attached on start. |
| `worktree rm` / `ps` / `list` | `orca.sh worktree …`, `loom worktree …` |
| `repo show` / `set-base-ref` | `orca.sh repo`, `orca.sh base-ref`, `loom repo`, `loom base-ref` |
| `automations create` / `list` / `run` / `remove` | `orca.sh automation …`, `loom automation …`. Verb only; Loom schedules nothing. |

Rules kept from Orca's guide:

- `check` is only ever called with `--peek` (or `inbox`).
- A failed `worker-start` is never retried.
- Silence or a timeout never authorizes a stop.
- Orca creates the workspace.
- `worker-abandon` is fencing, not a stop.

## 8. Identity

Unchanged from 0.5.0. The new verbs pass no name, model, or machine into the consumer's files. `compute` names a host, not a person. `model` names a provider model, not an author.

## 9. Acceptance

1. `bash ops/selftest.sh` exit 0.
2. `shellcheck -x ops/*.sh` exit 0.
3. `bash ops/mutate.sh` exit 0. Mutants m30–m34 belong to #36 (compute fallback, ignored compute, setup never applied, `--on` ignored, `loom verify` dropping `--on`). 0.6.0 adds:
   - m35 harvest never asks `worker-show`
   - m36 `check` scripted without `--peek`
   - m37 abandon recorded as a stop
   - m38 `ticket.sh` drops labels
   - m39 start ignores an unconnected Orca host
4. `loom compute --consumer consumers/smriti.toml` names a reachable host or exits 1.
5. A real read-only check: `loom hosts` prints the host list and exits 0.
6. No added file carries a personal name, a second account, or a credential.

## 10. Calls made here

- Placement is `--on <name>` from `orca host list`. `compute_selector` exists because Orca also accepts `--host ssh:<id>`, and Loom must not guess which one a given Orca build wants.
- Checks travel as a git bundle over ssh stdin, not a push. Loom still never pushes.
- `harvest` refuses only when `worker-show` says the dispatch is clearly active; an unparseable receipt does not block a conductor's explicit harvest.
- Autoscheduling and worktree deletion after merge are verbs, not policies.
- The pass-through verbs are smoke-tested in the selftest (they answer with one object); their deeper behaviour is Orca's and is not re-implemented here.
