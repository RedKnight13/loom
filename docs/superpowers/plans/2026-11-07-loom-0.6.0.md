# Loom 0.6.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close #36, #37, #38, and the #35 map, without changing the 0.5.0 call contract.

**Architecture:** Compute is a consumer declaration, resolved at run time. Checks travel to the host as a git bundle. Placement asks Orca for the host and refuses when it is not connected. Every Orca verb becomes a Loom verb with the same one-object envelope.

**Tech Stack:** Bash 3.2+, jq, git, gh, ssh/scp, Orca CLI.

**Spec:** `docs/superpowers/specs/2026-11-07-loom-0.6.0-design.md`

## Global Constraints

- One JSON object per `ops/loom` call; exit 0 iff `ok`.
- A declared compute host never falls back to the conductor's machine.
- Loom never connects an Orca host; it refuses.
- `check` only with `--peek`.
- Abandon is fencing, never a stop.
- No personal name, second account, or credential in any added file.

## Review Focus

- Unreachable host: 126 and `compute_unreachable`, not a checks failure.
- Setup failure: "could not run", not a failing test.
- Placement: missing or unconnected host refuses and leaves the record pending.
- Harvest: a clearly active dispatch refuses; unknown does not block.
- Labels: default only when the repo has `loom-ready`; duplicates collapse.
- Pass-through verbs return one object and never leak raw stdout.
