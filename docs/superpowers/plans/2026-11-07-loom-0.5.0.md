# Loom 0.5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One JSON call any harness can run, and close gaps #29, #30, #31, and #33.

**Architecture:** `ops/loom` is the only stdout a caller parses. It wraps the existing scripts. Ack and ignore are new records, not new worker states. Orca release is a confirmed CLI call, never a local terminal close.

**Tech Stack:** Bash 3.2+, jq, git, gh, shellcheck. No new language.

**Spec:** `docs/superpowers/specs/2026-11-07-loom-0.5.0-design.md`

## Global Constraints

- Version string is `0.5.0`, read from `VERSION`.
- Stdout of `ops/loom` is one JSON object. Exit 0 iff `ok` is true. Usage errors exit 2.
- Worker report states stay `ready|blocked|failed|waiting`.
- No personal name, second account, or credential in any added file.
- A failed Orca start is not retried. A stop or release Orca did not confirm changes nothing.
- `collect` never pushes.
- Selftest is offline. Mutants must make selftest fail.

## Review Focus

- A receipt whose only path is `workspace: "<repo-id>::<path>"` must still start. A missing `::` must not be treated as a path.
- Release before collect must refuse and leave the record unchanged.
- Ack hides the report row and does not hide an unreleased kept-open workspace.
- `.loom/` is copied to `$LOOM_STATE/<id>.evidence/` and is not in the commit. A symlink `.loom` is an error.
- `ops/loom` failure still prints one object and no other stdout.
