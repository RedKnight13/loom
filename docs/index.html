Loom is the thin layer between you and a coding agent that makes delegation safe and boring: one ticket, one isolated workspace, one structured report per turn, and a watchdog that ends silence. The agent never pushes. You are the only one who merges.

No server, no database, no model of its own. About 2,700 lines of bash and rules.

Why it exists

Handing a real repository to an agent fails in the same ways every time:

  • a worker hangs for ninety minutes looking alive;
  • liveness is inferred from a PID, or from prose;
  • a dead worker's spec is re-dispatched from memory;
  • the rules the work ran under live in nobody's file.

Loom turns each of those into a mechanism: an immutable Mandate, a private workspace, four report states, and a watchdog keyed to the process identity rather than a number.

One ticket, concretely

Issue #42: "Add --json to the CLI"

Mandate, written before any code:
  scope:      cmd/main.go, cmd/main_test.go
  out:        everything else
  done means: make check exits 0

Loom:      dispatch → private clone, branch add-json, no remote
Agent:     edits two files, appends REPORT.md:
             state: ready — added --json and a golden test
Loom:      commits that work as one commit on add-json
Watchdog:  fires only if the turn goes past limit_min
You:       loom verify add-json.1 → fresh clone, make check, exit 0
           loom collect add-json.1 → branch in your checkout
           git push, open PR, merge            ← the only manual step

Install

macOS or Linux, bash 3.2+, git, jq, gh, shellcheck. No runtime, no daemon.

brew install jq gh shellcheck
gh auth login
git clone https://github.com/RedKnight13/loom.git ~/loom
echo 'export PATH="$HOME/loom/ops:$PATH"' >> ~/.zshrc
exec $SHELL -l
cd ~/loom
bash ops/selftest.sh          # exit 0
shellcheck -x ops/*.sh ops/loom
bash ops/mutate.sh            # exit 0, SURVIVED=0

Or let an agent set it up

Paste one prompt into Claude Code or Codex. It checks prerequisites, clones and proves the checkout, asks for your repo and checks command, and stops before creating an issue. one click to copy

It runs the selftest, shellcheck, and the mutant suite; it never pushes, merges, or writes credentials, and it does not claim success without a captured exit code. Read it first: bootstrap.txt · the full page

Your first ticket

# 1. Register a consumer
cp consumers/example.toml consumers/myrepo.toml   # set repo, checks, worktrees

# 2. Write the ticket (opens a GitHub issue)
loom accept --consumer consumers/myrepo.toml --short add-json \
  --title "Add --json" --scope "cmd/main.go, cmd/main_test.go" \
  --out "everything else" --done "make check exits 0"

# 3. Dispatch, start, hold the clock
LOOM_REPO=~/src/your-repo loom dispatch --consumer consumers/myrepo.toml --issue 42
loom verify add-json.1 --baseline &
loom start add-json.1

# 4. On ready: re-check, collect, then you push and merge
loom verify add-json.1
loom collect add-json.1
loom ack add-json.1 "merged as #43"

What works today

AreaSupported
One callops/loom — one command, one JSON object, exit 0 iff ok
Ticketsrendered Mandate, parser self-check, repeatable labels
Executorslocal (private clone, no remote) and orca (supervised)
Placementfirst connected compute host; refuses when none, never local fallback
Checksfresh clone, local or over SSH; unreachable is “could not run”, not a failure
Reportsready | blocked | failed | waiting, one line per turn
WatchdogPID + start time, process-group kill, per-consumer limit
Attentionstatus shows only what needs a person; ack settles it
Capacityloom capacity suggests a worker count; workers caps open assignments and dispatch refuses past it
Limitsno push/PR/merge, no scheduler, no daemon, GitHub issues only

Local or supervised

Local executor

Zero extra dependencies. The worker gets a private clone with its own .git and no remote, so it can commit but cannot push.

Orca executor

Orca (MIT, 1.4.246+) supervises workers, places them on a compute host, and keeps their terminals and mail. Its app must be running. Loom refuses an unconnected host rather than using your laptop.

Guarantees

  • One live assignment per ticket; a second dispatch refuses.
  • A worker that exits without a state line is failed, not a mystery.
  • A recycled PID is never signalled: identity is PID plus process start time.
  • Corrupt state stops the scripts; it never reads as healthy.
  • The conductor re-runs your checks in a clone the worker never touched.
  • Every mechanism has a mutant: a fix without a test and a mutant is not landed.
