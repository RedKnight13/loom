Set up with your agent.

This is the setup prompt from bootstrap.txt. Read it, then paste it into a project session with file access and execution tools: a CLI agent or tool-enabled chat.

Open raw prompt

What to expect

  1. Update the Loom tools checkout: fetch origin, stop on a dirty, non-main or ahead checkout, and fast-forward only when cleanly behind.
  2. Discover existing tools and configuration, then run the checkout’s selftest and ShellCheck gates.
  3. Report Orca readiness, connected hosts and launchable agents, then reuse established choices for repository, trusted checks, workspace location, executor, worker count and worker agent. Ask only about unresolved choices; an existing Orca setup is reused, not reconfigured.
  4. Compare three task-appropriate coordination choices and observed agent/model recommendations for each role. Choose explicitly, keep the baseline, defer, or browse the full maintained pattern catalog. Unknown availability and cost stay unknown; selection does not authorize launches or configuration changes.
  5. Review a rendered mandate. Opening an issue or starting workers requires task-specific authorization; reuse it if already granted, otherwise ask for approval of the proposed action.

Install missing tools within granted authorization; ask only for missing permission. Plain chat without project access and execution tools remains unwired: nothing is installed or persisted. A session without shell access reports command checks as not run.

Read setup results in stages

Setup reports each level separately:

  • Structural wiring: configuration and session-entry instructions are inspected. A file’s presence does not prove a fresh agent loads it.
  • Offline evidence: selftest and ShellCheck exits are reported separately from the fixed calibration drill. None proves live consumer acceptance.
  • Live workflow proof: an authorized real ticket, worker, harvest, and verification sequence has produced evidence and passed your project’s checks. Otherwise, report not run. Human review still follows.

Using the paths defined in the manual setup reference, run bash "$LOOM_TOOLS/ops/loom" calibrate --consumer "$FILE" --check first. Reuse current evidence; review missing or drifted evidence before explicitly recording with bash "$LOOM_TOOLS/ops/loom" calibrate --consumer "$FILE", then check again. Recheck at session entry and before delegation. If the installed CLI lacks calibration, report it as not run and block dependent delegation.

The agent must enforce these checks; dispatch and launch are not automatically guarded. Setup checks and an offline drill do not establish that real project work has succeeded. Treat a level that was not run as unverified.

The full prompt

After setup, follow the local daily loop. For Orca, use the Orca executor reference. Start with a small task and keep review in your hands.
